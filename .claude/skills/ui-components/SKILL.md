# UI components & design system

Fast-start router. **Authoritative reference:** [`knowledge-base/handbook/design/design_guidelines.md`](../../../knowledge-base/handbook/design/design_guidelines.md) (normative rules) + its operational companion [`visual-consistency-standard.md`](../../../knowledge-base/handbook/design/visual-consistency-standard.md) (spacing/elevation scales, icon registry, `<Logo>`/white-label, empty-state + adoption checklists), and the code itself — `client/src/index.css` (CSS-variable tokens) + `tailwind.config.ts` + `client/src/components/ui/**` are the source of truth. Page map: [`app-guide/07-frontend.md`](../../../knowledge-base/handbook/app-guide/07-frontend.md).

## Working alongside other sessions
Other sessions (and the owner) edit this repo concurrently. Before you pick a file: `git fetch origin`, read what merged since you last looked, and treat **any file in another session's open PR as claimed** — pick something else rather than planning to rebase. Open PRs from a base ≤2 commits behind `main`. When work is already in flight, prefer helping it land — fix a red CI, verify an unreviewed PR, supply a missing test — over opening another. Authoritative contract: [`routines/CHARTER.md`](../../../knowledge-base/routines/CHARTER.md) (claim lock §5, honesty rails §10).

Two standing lessons that bind here: **business logic does not live in a `.tsx`** — pure math/rules go to a `client/src/lib/*.ts` module with a colocated test, and the component keeps JSX/state/mutations (`affordabilityEstimate.ts`, `rentVsBuyEstimate.ts` are the shape). And when you move code, **write the characterization test against the original location and see it green first** — then change only the import.

## Non-negotiables
- **No raw Tailwind palette classes** (`text-emerald-600`, `bg-amber-100`, …). `pnpm guard:tokens` (`scripts/design-token-guard.cjs`) runs **in the required CI gate** (since 2026-07-19) and fails the PR on any count over baseline. Use semantic tokens and `<Badge>`/`<Alert>` variants; run it locally before pushing.
- **Calm Emerald** (2026-08-18 repaint of Royal Blue Emerald — the royal-blue chrome is retired as visual noise; Better.com's dashboard is the lead reference): stark-white surfaces, neutral slate ramp, near-black slate type (#0F172A), **light navigation chrome** (white sidebar/footer via `--sidebar`, slate text, hairline separation; `--accent` is the neutral slate-100 menu-hover surface, not a brand color). **Emerald = forward action only** (`bg-primary` #047857, AA 5.49:1 — raw #10B981 must not carry white text). Hierarchy through the value ramp + whitespace, not hue — **no colored bands as page furniture**: page headers are eyebrow + `<h1>` + muted subtitle on the app ground, never a `bg-primary`/`bg-accent` gradient band with white text (dark ink `precision.950/900/700` survives only in the persona-page final-CTA closers). Cards = white + 1px slate-200 hairline; **⏳ on the app gray ground (`bg-surface`) a content card carries `shadow-card`** (=`--shadow-sm`; hover `shadow-card-hover`, emphasis `shadow-card-lg`) — the elevation reversal, rolled out surface-by-surface. Overlays keep Radix shadows; no ad-hoc `shadow-2xl`/`shadow-lg border-0` on content cards.
- **Spacing/scaffold:** authed pages use `PageShell` (owns width/gutter `px-4 sm:px-6 lg:px-8`/vertical rhythm). Canonical widths `narrow` 2xl / `content` 4xl / `wide` 6xl / `full` 7xl; section rhythm `space-y-6` (`-4`/`-8` tiers); card padding `p-6` (dense `p-4`); page `<h1>` `text-2xl sm:text-3xl` (use `<Heading>`/`<Text>`). Don't hand-roll `min-h-screen` page wrappers.
- **WCAG 2.1 AA (enforced):** status color as text-on-canvas is a fail → use the `*-subtle` pairs. Icon-only controls **require `aria-label`**. Labels always visible (no placeholder-only). Touch targets ≥44px. `<SkipLink/>` is the first focusable element; form errors announce via `role="alert"`.
- **Icons:** import by **semantic name from `client/src/lib/icons.ts`** (one glyph per concept), not directly from `lucide-react`; size rungs `h-4`/`h-5`/`h-3.5`/`h-6`/`h-8`/`h-10`. No emoji/raster glyphs. Zero-states use `<EmptyState>` (+ a `components/illustrations/` spot art), never a hand-rolled icon-in-a-gray-circle.
- **Branding/white-label (⏳):** private/authenticated surfaces are tenant-brandable — `BrandingProvider` overrides only the **brandable** tokens (`--primary`/`--ring` + the rail's `--sidebar-primary`/`--sidebar-ring`) per tenant, never inline hex; fixed tokens (neutral ramp, the chrome `--sidebar`/`--accent`, `--surface`+elevation, semantic status) never change — brand shows through actions + logo, never by painting navigation; public surfaces stay Homiquity. Use `<Logo>` (brand/), not a hardcoded `homiquity` span.
- **Data:** never `fetch()` in a component — use `queryClient`/`apiRequest` (TanStack Query) so auth, errors, and cache invalidation stay consistent. Forms use react-hook-form + the shared Zod schemas.
- **The key IS the request.** Never write a `queryFn` — `buildQueryUrl` derives the URL *from* the queryKey, which is the only reason the cache key and the request can't disagree. A hand-written one is a second spelling of the URL that nothing checks: four shipped naming a path the server doesn't serve (`["/api/predictions/me", id]` → `/api/predictions/me/<id>`, but the route reads `?applicationId=`), so the key was decorative and deleting the "redundant" queryFn 404'd the page. Query-string params ride as a **trailing object** — `["/api/x", { price }]` → `/api/x?price=…` — built from a factory in `client/src/lib/queryClient.ts`. Public endpoints (signed-out visitors) use `queryFn: getPublicQueryFn<T>()`, the one sanctioned exception. `pnpm guard:querykeys` (3 guards: shape, reachability, transport) runs **in the required CI gate**.
- **Live/streamed state goes in the query cache, not `useState`.** An SSE or WS handler writes with `setQueryData` against a factory key, so the value stays shareable, invalidatable, and has an error state. It also needs an `onerror` that distinguishes a transient reconnect (`readyState CONNECTING`) from a permanent failure (`CLOSED`) — a 401/502 makes the browser stop retrying *silently*, and the surface must say the channel is lost rather than keep rendering a frozen value as current. Pattern: `hooks/useAutopilotStatus.ts`.
- **One page, one data-flow direction.** Within a page, either the container fetches and passes data down, or each child fetches its own — don't mix, and prefer child-fetches-its-own (independently testable, no invisible child→parent-key coupling). `pages/staff/BorrowerFile.tsx` is the documented mixed case, migrating child-by-child.
- **Testability:** every interactive or asserted element gets a kebab-case `data-testid` — and behavioral UI changes get a **component test first**: colocated `client/src/**/*.test.tsx`, run by `vitest.client.config.ts` (happy-dom, in the CI gate via `pnpm test`; `pnpm test:client` alone). Assert on testids/labels, not DOM shape; browser verification is for visuals/E2E only. Seed patterns: `DocumentStatusBadge.test.tsx` (vocabulary pin incl. the Reg N never-"Approved" rule), `ui/button.test.tsx` (user-event interaction).

## Where it lives
`client/src/components/ui/` (30 token-driven primitives: Button/Badge/Alert/Card…) · `client/src/index.css` + `tailwind.config.ts` (tokens) · `client/src/App.tsx` (routes, role-gated trees) · pages under `client/src/pages/<audience>/`.

Adding a status color? Add a `<Badge>/<Alert>` variant + `*-subtle` tokens (light+dark, AA-verified) — never a one-off palette class.
