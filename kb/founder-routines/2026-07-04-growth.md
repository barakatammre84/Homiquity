### 4. Metric-gate readiness (70% pull-through / 12-day cycle / 30% agent-sourced)

Not measuring anything today (correctly — pre-launch, no real traffic). Checked whether the plumbing to measure it *would* exist once traffic arrives:
- **Pull-through & cycle-time: plumbing exists, unassembled.** `loanApplications` only keeps a single mutable `updatedAt` (overwritten on every change, `shared/schema/lending.ts:281`) — no per-stage timestamp columns. But every status transition is separately captured with `previousStatus`/`newStatus` and a timestamp in `audit_logs` via `logAudit(req, "loan_application.status_changed", ...)` (`server/routes/lending.ts:1496`). That's enough raw data to compute both gates (first `loan_application.created` → status reaches `funded`), it just has no query/report built on top of it yet.
- **Lead → application attribution: exists.** `leads.convertedApplicationId` + `convertedUserId` + `convertedAt` (`shared/schema/leads.ts:70-72`) link a lead to its resulting application, and `leads.source`/`utmSource` capture channel.
- **Agent-sourced %: no plumbing at all.** The only "agent" system in the codebase is `agent_referral_requests` (`shared/schema/admin.ts:786`) — that's Homiquity referring a borrower **out** to a real-estate agent, the opposite direction from an agent **sending** Homiquity a borrower lead. The `leads.source` enum documented in code (`zillow_connect, zillow_quotes, lendingtree, organic, referral, direct, other`) has no agent/realtor-specific value. If agent-sourced leads start arriving before this is fixed, they'll land under generic `"referral"` and be indistinguishable from any other referral — the 30% gate would be unmeasurable even in hindsight.
